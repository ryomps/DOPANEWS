# DOPANEWS

ニュース記事をラップバトルに変換し、聴いた後に自分の考えを振り返るローカルWebアプリです。

## 起動とAPIキー設定

1. `config.example.json` を `config.local.json` にコピーします（既にある場合はそのまま使用）。
2. `GeminiApiKey` と `MurekaApiKey`、ニュース検索・記事作成用の `OpenAIApiKey` に発行済みのキーを一度だけ設定します。
3. Windowsで `start_server.bat` を実行し、`http://localhost:8080/` を開きます。

APIキーを画面で入力する必要はありません。ローカルサーバーが設定を読み込み、OpenAI・Gemini・Murekaへ送信します。ブラウザにキーを返しません。設定変更は次のAPI呼び出しから反映されます。環境変数 `GEMINI_API_KEY` / `MUREKA_API_KEY` / `OPENAI_API_KEY` も使用でき、ファイル設定を優先します。

`config.local.json` と `.local/` はGit管理対象外です。ブラウザの以前のlocalStorageに保存されたキーは、この方式では使用しません。`index.html` の直接起動や別の静的サーバーでは生成・保存機能は使えません。

楽曲生成モデルは `mureka-9`（Mureka 9.0）、生成数は1曲に固定しています。最新版への自動切り替えは行いません。

Geminiだけ設定した場合は歌詞＋内蔵ビートで再生します。キーなしでもプリセットデモを体験できます。

## ニュースの自動取得・原稿生成

- トップ画面の「いまの話題から、ニュースを作る」に、Yahoo!ニュース公式RSSの主要・経済・科学の見出しを自動取得します。15分間キャッシュし、一覧の閲覧にはAI APIを使いません。更新失敗時は取得日時と保存済みであることを表示します。
- 「根拠を調べて記事を作る」を押すと、OpenAI Responses APIのWeb検索（gpt-6-luna固定）で原資料のURLを探します。モデルが本文中に書いたURLではなく、実際の検索ツールの参照先を使います。
- 検索後はサーバーが原資料本文を取得し、OpenAI gpt-6-lunaが事実抽出・執筆・原稿審判を最大3回のAPI呼び出しで実行します。記事作成ではGeminiを使用しません。失敗時の自動再試行・別モデルへの切り替えはありません。
- 検索対象のサイトは固定せず、公式発表を優先して公開HTML資料を探します。公式資料が見つからない場合は報道も候補とします。1件の本文資料でも作成しますが、独立した複数確認済みとは表示しません。PDF・転送・本文を取得できないページ・個別の利用制限を検出した資料は採用しません。原文に存在しない引用が返った場合も停止します。検索で見つかること自体は再利用許諾を意味しません。
- 記事には段落ごとの事実ID、元資料のURL・取得日時・配信元（既知の公的資料は利用条件へのリンク）、根拠原文、未確定事項、取得失敗の資料を表示します。資料本文は冒頭最大2万文字の範囲を使用します。原稿審判に指摘がある場合は内部で保留とし、その原稿・判定の詳細・ラップ生成ボタンは表示しません。
- 「この記事でラップを生成する」から既存の作詞・歌詞審判・Mureka 9へ進めます。作詞と審判には、生成原稿を根拠にした自己確認を避けるため、採用した事実と実際の根拠原文を渡します。
- `.local/news/` に取得見出し、原資料、事実一覧、原稿、審判結果を保存します。保存済み記事を開いてもAPIは使用しません。判断保留の再調査は明示操作でのみ実行します。生成済みの確認済み原稿は再生成しません。
- 指定の8サイトは画面の「情報源の対応状況」で確認できます。自動取得はYahoo!の見出しのみです。他7サイトは参照リンクで、各サイトの本文を比較したとは表示しません。[調査記録と設計](docs/multi-source-news.md)も参照してください。
- AIの検索・校閲にも誤りはあり、第三者の権利、一次資料の正確性、原稿の事実性を保証するものではありません。根拠資料は画面から確認できます。
- 作成中・失敗のメッセージは、選択した記事カード内に表示します。OpenAIの利用上限（429）、接続設定、通信障害、対応資料の不足を区別し、上限時は利用状況へのリンクを表示します。審判の詳細は表示しません。
- 作成失敗の工程・安全なエラー分類は `.local/news/failures/` に保存します。APIキー・プロバイダーの生のエラー本文は記録しません。利用枠の変更はアプリから行いません。

## OpenAI検索の開発中の動作

- 開発期間中は話題ごと・日次・累計の検索回数上限を設けません。過去の回数記録は削除せず引き継ぎます。APIサービス側の残高・レート制限は適用されます。
- API側にもmax_tool_calls=1、並列ツール実行なし、最大出力800トークン、タイムアウト60秒、レスポンス保存なしを指定します。モデルはgpt-6-luna固定で、自動フォールバックしません。
- 呼び出し前に回数を永続化します。失敗・タイムアウト・結果不正も消費済みとして数え、失敗後の再検索はボタン操作時に限ります。自動再検索はしません。既存の旧形式の検索記録も1回分として引き継ぎます。実行中・終了不明の予約記録が残る場合は二重消費を防ぐため停止します。キー未設定・入力不正では外部APIを呼びません。
- 検索成功時はURL一覧をローカル保存し、後続の記事処理が失敗しても再利用します。保存済み記事・検索の再利用には追加の検索APIを使いません。
- 回数と予約は.local/news/openai-search-budget.jsonと.local/news/searches/に保存します。ファイルロックで複数サーバーの二重消費を防ぎます。記録が壊れている、またはロックが残っている場合は停止します。回数制限解除のために記録を削除する必要はありません。
- 開発中のアプリ内検索回数上限・請求額上限はありません。OpenAIのモデル・検索料金、後続のGemini、音源生成のMurekaはそれぞれ料金体系と利用枠に従います。他アプリからのAPI利用は制限できません。
- OpenAIのキーはconfig.local.jsonのOpenAIApiKeyか環境変数OPENAI_API_KEYに設定します。開発用パネルから保存することもできます。ブラウザへのキー返却・localStorage保存はしません。
- 実装仕様の参照：[Web検索](https://developers.openai.com/api/docs/guides/tools-web-search)、[GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)、[料金](https://developers.openai.com/api/docs/pricing)。プロジェクトでの実利用可否はキー設定後に確認してください。

## 歌詞の読み方

- Geminiは通常表記の `lyric` と、同じ内容・行数の歌唱用かな表記 `lyric_reading` を同時に生成します。
- ステージには `lyric` を表示し、Murekaには `lyric_reading` を送ります。漢字に括弧で読みを足す方式ではありません。
- 数字・英字・固有名詞も文脈に合わせて読みへ変換します。Geminiの読みの判断やMurekaの歌唱が必ず正しくなることを保証する機能ではありません。
- かな表記の返却歌詞も照合し、元の表示歌詞の該当行を強調します。表示と読みの行数が合わないなどの不正な応答は、最大3回の作詞枠内で修正し、解消しない場合は楽曲生成前に停止します。
- 既存の保存曲はそのまま再生できます。既存音声の発音は変わらず、新しく生成する曲から適用されます。

## 保存・再生

- 新しく生成したラップは自動保存します。「今のラップを保存」でプリセットを保存したり、保存失敗を再試行できます。
- `.local/library/` に元記事・歌詞・同期情報をJSONで保存し、Mureka音声はMP3としてダウンロードします。音声URLだけの保存ではないため、生成元のURLが期限切れになっても再生できます。
- 起動時に「保存したニュースラップ」一覧を読み込みます。「このラップを聴く」で元記事・歌詞・音声を復元できます。
- 再生ボタンは「一時停止」「再生・再開」に切り替わります。途中からの再開、各バースへの移動、終了後の聴き直しに対応します。
- 保存前にページを閉じて失われた過去の生成曲を、自動的に取り戻す機能はありません。手元のMP3読み込みは再生用で、履歴への取り込みは未対応です。
- 振り返りの選択・メモは従来どおりページ内で保持され、履歴JSONには保存しません。

## バックグラウンドの内容確認

- 歌詞・原稿・音源の審判は内部で実行し、PC・スマホとも判定、指摘、審判専用の操作ボタンを表示しません。既存の保存データにある審判結果もUIに表示しません。
- 歌詞は初回を含む最大3回まで作成します。事実・読み方の不合格や判断保留の場合は、直前の指摘と元記事を渡して自動で修正します。読み表記やJSON形式の不正も同じ3回の枠に含めます。
- 合格した歌詞だけをステージへ設定し、Mureka 9で1曲生成します。3回とも通らない場合は音源を生成せず、画面には作成を完了できなかった旨だけを表示します。作詞のみモードにも同じ上限を適用します。
- 通信・認証・審判APIの失敗は、歌詞の内容不合格とは区別してその時点で停止します。自動で音源を作り直しません。原稿の再作成は明示操作のままで、歌詞の3回の上限とは別です。
- 音源生成・保存後は実際のMP3をGeminiへ送り、内容をバックグラウンドで照合します。音源審判の指摘を理由とするMurekaの再生成はしません。
- 内容確認モデルはGemini 3.1 Flash-Lite。再作詞・審判はGeminiの利用料金が発生します。各試行の結果は保存するラップの内部データに保持します。元資料との照合であり、外部の真偽を保証しません。

## 検証

```powershell
node --test tests/*.test.cjs
powershell -NoProfile -ExecutionPolicy Bypass -File server.ps1 -NoBrowser
```

追加依存パッケージはありません。Node.js 22以降が必要です。Windowsの起動用バッチからNode.js製ローカルサーバーを起動します。

## 曲の構成

96 BPM・4拍子・8小節×4本を1曲としてMureka 9で生成します。KENTA→REINA→KENTA→REINAの男女交互歌唱を指定し、音声生成は1回・1曲です。8小節は計算上20秒ですが、生成音源の正確な秒数・声の交代は保証されません。20秒への強制編集やパート別生成は行いません。歌詞表示はMurekaの返却時刻を優先します。既存の保存音源はそのまま再生できます。

## 伴奏にラップを追加

左パネルの「伴奏にラップを追加」で伴奏を選択し「伴奏をアップロード」を押します。MP3/M4Aは10MB、16bit PCM WAVは40MB・10分以内。WAVは同梱のlamejs 1.2.1（vendor/）でMP3へ変換し、サーバー経由でMurekaにpurpose=audioのmultipartで送ります。アップロード済み音声とタスク情報はGit対象外の.local/backing-uploads/に保存します。

開始・終了秒、担当MC、表示歌詞、かな表記の読みを入力し「指定区間にラップを追加」を押します。「このバースの歌詞をセット」で現在の台本からコピーできます。元記事はニュース記事入力欄を使います。Geminiの歌詞審判を通過した場合のみ、Mureka /v1/track/generateにgenerate_type=Vocals、vocal_gender、ミリ秒の区間を送ります。1操作につき1区間を生成します。生成結果をステージで再生・自動保存し、音源審判に送ります。返却音源の構成や区間の厳密な遵守は生成結果によるため、元伴奏の試聴と比較してください。自動の追加生成はしません。

直接開く： http://localhost:8080/?studio=backing
検証： node --test tests/backing.test.cjs tests/server.test.cjs tests/regressions.test.cjs

検索結果のURLは公開HTTPSに限定し、本文取得前にDNSを確認して公開IPv4へ接続先を固定します。ローカルIP・認証情報付きURL・任意ポート・転送は取得しません。本文は最大2万文字で、見出しや検索要約だけでは記事化しません。

記事の各OpenAI工程にはResponses APIのtext.format（strict JSON Schema）で必須項目・型・配列の件数を指定します。短い資料は1事実・1段落でも作成し、根拠IDと原文の照合は維持します。本文取得に失敗した場合はカード内の「別の情報源で再検索（OpenAIを使用）」から手動で再検索できます。前回のURLを除外し、自動再検索はしません。原稿形式・根拠不足・本文取得失敗は別のエラーとして表示し、失敗した工程と安全な原因分類を.local/news/failuresに保存します。

生成記事の「この記事でラップを生成する」は、選んだ記事名と進捗をスマホのステージ内に表示します。成功するまで前のステージは隠し、失敗した場合は理由と再試行ボタンを同じ画面に表示します。開発用左パネルを開かずに状態を確認できます。
