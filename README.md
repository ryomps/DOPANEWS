# DOPANEWS

ニュース記事をラップバトルに変換し、聴いた後に自分の考えを振り返るローカルWebアプリです。

## 起動とAPIキー設定

1. `config.example.json` を `config.local.json` にコピーします（既にある場合はそのまま使用）。
2. `GeminiApiKey` と `MurekaApiKey` に発行済みのキーを一度だけ設定します。
3. Windowsで `start_server.bat` を実行し、`http://localhost:8080/` を開きます。

APIキーを画面で入力する必要はありません。ローカルサーバーが設定を読み込み、Gemini・Murekaへ送信します。ブラウザにキーを返しません。設定変更は次のAPI呼び出しから反映されます。環境変数 `GEMINI_API_KEY` / `MUREKA_API_KEY` も使用でき、ファイル設定を優先します。

`config.local.json` と `.local/` はGit管理対象外です。ブラウザの以前のlocalStorageに保存されたキーは、この方式では使用しません。`index.html` の直接起動や別の静的サーバーでは生成・保存機能は使えません。

楽曲生成モデルは `mureka-9`（Mureka 9.0）、生成数は1曲に固定しています。最新版への自動切り替えは行いません。

Geminiだけ設定した場合は歌詞＋内蔵ビートで再生します。キーなしでもプリセットデモを体験できます。

## 歌詞の読み方

- Geminiは通常表記の `lyric` と、同じ内容・行数の歌唱用かな表記 `lyric_reading` を同時に生成します。
- ステージには `lyric` を表示し、Murekaには `lyric_reading` を送ります。漢字に括弧で読みを足す方式ではありません。
- 数字・英字・固有名詞も文脈に合わせて読みへ変換します。Geminiの読みの判断やMurekaの歌唱が必ず正しくなることを保証する機能ではありません。
- かな表記の返却歌詞も照合し、元の表示歌詞の該当行を強調します。表示と読みの行数が合わないなどの不正な応答は、楽曲生成前に停止します。
- 既存の保存曲はそのまま再生できます。既存音声の発音は変わらず、新しく生成する曲から適用されます。

## 保存・再生

- 新しく生成したラップは自動保存します。「今のラップを保存」でプリセットを保存したり、保存失敗を再試行できます。
- `.local/library/` に元記事・歌詞・同期情報をJSONで保存し、Mureka音声はMP3としてダウンロードします。音声URLだけの保存ではないため、生成元のURLが期限切れになっても再生できます。
- 起動時に「保存したニュースラップ」一覧を読み込みます。「このラップを聴く」で元記事・歌詞・音声を復元できます。
- 再生ボタンは「一時停止」「再生・再開」に切り替わります。途中からの再開、各バースへの移動、終了後の聴き直しに対応します。
- 保存前にページを閉じて失われた過去の生成曲を、自動的に取り戻す機能はありません。手元のMP3読み込みは再生用で、履歴への取り込みは未対応です。
- 振り返りの選択・メモは従来どおりページ内で保持され、履歴JSONには保存しません。

## AI審判

- 新しい歌詞の生成後、元記事・表示歌詞・音声用の読みをGeminiで照合します。指摘あり・判断保留・審判失敗の場合はMurekaの呼び出し前に停止します。
- 音源を生成・保存すると、保存したMP3そのものをGeminiに送り、バックグラウンドで歌詞の違い・読み間違い・記事との食い違いを確認します。歌詞テキストだけから音源を検証したと扱うことはしません。
- 指摘は引用・理由・元記事の根拠・修正案とともに表示します。外部情報の検索によるファクトチェックではなく、元記事との照合です。記事自体の誤りやAIの誤判定を排除するものではありません。
- 再生成は自動で行いません。「指摘を反映して再生成」を選んだ場合だけ、指摘を参考に新しい歌詞を1回生成し、再び歌詞審判を通してからMureka 9で1曲生成します。「今回は再生成しない」で止められます。
- 歌詞の再確認で指摘がなければ、追加の確認ボタンを挟まず音源生成へ進みます。歌詞の再生成は行いません。作詞のみモードは内蔵ビートへ進み、生成済み音源の再確認はGeminiのみ使用します。
- 審判モデルは `gemini-3.1-flash-lite`。通常は歌詞と音源で各1回のGemini API使用が追加されます。審判の失敗時に自動再試行しません。Murekaの追加消費は再生成を選んだ場合だけですが、審判自体にはGeminiの利用料金が発生します。
- 音源判定は保存履歴に保持し、聴き直しで審判を繰り返しません。音源が未保存・12MB超・聞き取り不明などの場合は、指摘なしとせず未確認・保留を表示します。旧履歴やプリセットは審判済みとは扱いません。

## 検証

```powershell
node --test tests/regressions.test.cjs tests/server.test.cjs
powershell -NoProfile -ExecutionPolicy Bypass -File server.ps1 -NoBrowser
```

追加依存パッケージはありません。Node.js 22以降が必要です。Windowsの起動用バッチからNode.js製ローカルサーバーを起動します。

## 曲の構成

96 BPM・4拍子・8小節×4本を1曲としてMureka 9で生成します。KENTA→REINA→KENTA→REINAの男女交互歌唱を指定し、音声生成は1回・1曲です。8小節は計算上20秒ですが、生成音源の正確な秒数・声の交代は保証されません。20秒への強制編集やパート別生成は行いません。歌詞表示はMurekaの返却時刻を優先します。既存の保存音源はそのまま再生できます。

## 伴奏にラップを追加

左パネルの「伴奏にラップを追加」で伴奏を選択し「伴奏をアップロード」を押します。MP3/M4Aは10MB、16bit PCM WAVは40MB・10分以内。WAVは同梱のlamejs 1.2.1（vendor/）でMP3へ変換し、サーバー経由でMurekaにpurpose=audioのmultipartで送ります。アップロード済み音声とタスク情報はGit対象外の.local/backing-uploads/に保存します。

開始・終了秒、担当MC、表示歌詞、かな表記の読みを入力し「指定区間にラップを追加」を押します。「このバースの歌詞をセット」で現在の台本からコピーできます。元記事はニュース記事入力欄を使います。Geminiの歌詞審判を通過した場合のみ、Mureka /v1/track/generateにgenerate_type=Vocals、vocal_gender、ミリ秒の区間を送ります。1操作につき1区間を生成します。生成結果をステージで再生・自動保存し、音源審判に送ります。返却音源の構成や区間の厳密な遵守は生成結果によるため、元伴奏の試聴と比較してください。自動の追加生成はしません。

直接開く： http://localhost:8080/?studio=backing
検証： node --test tests/backing.test.cjs tests/server.test.cjs tests/regressions.test.cjs
