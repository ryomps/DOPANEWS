# ドパNEWS

ニュースを読み、二人のMCが異なる立場から語るラップを聴いて、自分ならどう考えるかを振り返るWebアプリです。GifuBroが開発しています。

## 使い方

1. ニュース一覧から記事を選びます。ジャンルで絞り込むほか、検索画面でキーワードやタグを使えます。
2. 記事画面の「MCバトル」を押し、12人のキャラクターから二人を選びます。「MC決定」で双方の立場を確認し、「VS」から再生画面へ進みます。
3. ラップを聴きながら、歌っているMCと歌詞を追えます。再生位置の調整、前後のバースへの移動、音量調整にも対応しています。
4. 投票では、自分の意見に近い方か「どちらともいえない」を選べます。「Library」から投票を見返し、保存済みのバトルを聴き直せます。

「大人ドパガキ」問題や自転車の青切符など、音源付きの記事はAPIキーなしで試せます。記事には出典を示し、バトルの主張や歌詞は創作として扱います。

## 起動する

Node.js 22以降が必要です。Windowsでは `start_server.bat` を実行し、[http://localhost:8080/](http://localhost:8080/) を開きます。追加の依存パッケージは不要です。

スマホで試すときは、PCとスマホを同じネットワークに接続して、プロジェクトのフォルダで次を実行します。

```powershell
node server.cjs --port 8080 --lan --no-browser
```

スマホでは起動時に表示されるPCのIPアドレスを使います。`start_phone.bat` で起動する場合は、起動画面に表示される3001番ポートのURLを開きます。

## 設計と実装

- 記事を探す画面、キャラクター選択、バトル再生、投票、ライブラリを実装しました。再生中は、歌詞の行時刻に合わせて表示を強調し、歌い手が変わるとステージの演出も切り替えます。
- ニュースの候補はYahoo!ニュース公式RSSの見出しから取得し、15分間キャッシュします。記事を作成する操作を受けて、OpenAIの検索で根拠資料を探し、取得した本文から原稿を作ります。アプリ側で、根拠として返された引用が本文にあることや、各段落が採用した事実を参照していることを確認します。[ニュース作成の設計](docs/multi-source-news.md)
- バトル生成では、Geminiで表示用の歌詞と歌唱用のかな表記を作り、Lyria 3.5で声ごとに音源を生成します。Whisperの単語時刻を歌詞と照合し、アプリ側で歌唱区間を切り出して交互につなぎます。音声の編集にはWeb Audioを使用します。
- 確認処理に指摘がある歌詞は、初回を含めて最大3回の範囲で修正します。原稿や歌詞は採用した資料に照らして確認します。資料の内容や生成結果の正確さは、掲載された出典から利用者も確認できます。
- 生成したバトルは音源・歌詞・同期情報とともにサーバーの `.local/library/` に保存します。投票はブラウザに保存し、同じバトルに投票し直すと前の選択を上書きします。

## 新しい記事やバトルを作る

1. `config.example.json` を `config.local.json` にコピーします。設定済みのファイルがあればそのまま使えます。
2. `OpenAIApiKey`（記事の検索・作成、音声認識）と `GeminiApiKey`（作詞・内容確認・音源生成）に発行済みのキーを設定します。伴奏関連の機能を使う場合は `MurekaApiKey` も設定します。
3. 開発パネルに記事URLまたは本文を入力して生成します。話題一覧から根拠を検索して記事を作り、その記事からラップ生成へ進むこともできます。

通常の音源生成にはLyriaを使えるGemini APIの利用枠が必要です。作詞のみのモードでは内蔵ビートを使います。伴奏にラップを追加するモードでは、アップロードした伴奏の指定区間をMurekaで処理します。固定ビートとGemini TTSを組み合わせるモードもあります。

キーはサーバーで読み込みます。環境変数 `OPENAI_API_KEY`、`GEMINI_API_KEY`、`MUREKA_API_KEY` でも設定でき、ファイルに値がある場合はそちらを優先します。`config.local.json` と生成データの `.local/` はGit管理対象外です。

同じ設定で生成済みの元音源や認識結果は再利用します。生成結果が未確定のまま通信が切れた場合は、重複送信を防ぐ記録を残します。再試行の前にAPIの利用履歴と `.local/lyria/` の記録を確認してください。
